# Onboardie — Architecture Notes

AI onboarding coach for new hires at German Mittelstand companies. Two portals (New Hire, Manager), company-isolated content, AI coach grounded strictly in manager-published content.

## Stack
- TanStack Start v1 (React 19, Vite 7, SSR, server functions via `createServerFn`), built with Nitro and deployed to Netlify (any Nitro preset works).
- Tailwind CSS v4 (`src/styles.css` tokens), shadcn/ui components (`src/components/ui`).
- Supabase (Postgres + Auth + RLS). Email/password auth only.
- AI: any OpenAI-compatible Chat Completions API (`src/lib/ai-gateway.server.ts`), configured with `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`. Failures are logged to `ai_failure_log`.
- Notion API (optional) as a shared "mockup role" content source (`src/lib/notion.server.ts`, `notion-publish.server.ts`) — needs `NOTION_API_KEY`; pages must be shared with the integration.
- MCP server (`src/lib/mcp`, `src/routes/mcp.ts`, `[.mcp]/*`): tools `get_role_content`, `ask_onboarding_coach`.
- File text extraction in the browser: `mammoth` (docx), `pdfjs-dist` (pdf), plain text/RTF (`src/lib/extract-file-text.ts`).

## Environment variables
- Client: `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`
- Server: `SUPABASE_SERVICE_ROLE_KEY` (`SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` fall back to the `VITE_` values), `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, optional `NOTION_API_KEY`. See `.env.example`.

## Database (apply `supabase/migrations/*.sql` in order)
- `companies` (id, name, domain, invite_code unique `ONB-XXXXXX`).
- `profiles` (id = auth user, full_name, email, role_title, start_date, company_id).
- `user_roles` (user_id, role enum `manager` | `new_hire`) — roles never on profiles.
- `role_content` (company_id, role, sections jsonb, updated_at) — published roles.
- `role_drafts` — unapproved/unstructured drafts per company (status: draft / revised / raw).
- `company_docs` (company_id, title, content) — company-wide policies used by coach retrieval.
- `coach_questions` (company_id, question text, topic) — anonymous, manager insights only.
- `company_updates` — banner text per company.
- Functions: `handle_new_user()` trigger (creates profile + role; groups by `invite_code` metadata first, else `company_for_user(email)`: work domain → shared company, free-mail → private company), `current_company_id()`, `has_role()`, `join_company_by_code(text)`, `my_company_invite()`.
- RLS: every table scoped to `current_company_id()`.

## Key flows
1. **Sign-up** (`routes/signup.tsx`): name, email, role (New Hire/Manager), job title, start date, optional invite code → metadata → trigger.
2. **Protected layout** `routes/_authenticated/route.tsx` redirects to `/login`; manager vs new-hire redirect by `user_roles`.
3. **Upload** (`upload-content.tsx`): paste + multiple files, each tagged Role-specific or Company-wide; "Save as Draft" (raw) or "Structure This" → `structure.functions.ts` asks AI for JSON sections: overview, learning plan (Week 1/Week 2/Month 1–3), FAQs (categorized), tools, contacts.
4. **Review & Approve** (`review-approve.tsx`): list of drafts with status, inline edit per section, Approve & Publish → `publish.functions.ts` upserts `role_content`; mockup roles copyable.
5. **New Hire pages** (dashboard, ai-coach, learning-plan, resources, contacts, role-overview, settings) read `live-content.functions.ts` — content matched strictly to the hire's own `role_title` (normalized); empty state if no match. Query key includes role title so role changes refetch.
6. **Working days** (`working-days.ts`): Mon–Fri, minus Bavarian holidays, Day 0 = start date; drives the 30/60/90 tracker and calendar.
7. **AI Coach** (`coach.functions.ts`): system prompt with grounding rules; primary = hire's role content; secondary = keyword retrieval (`retrieval.server.ts`) over *general* sections of other company roles + `company_docs` + Notion; contact directory for the "not covered → who to contact" fallback; logs question anonymously with topic.
8. **Preview as New Hire** (`preview.ts`, `preview.functions.ts`, `preview-banner.tsx`): manager selects a published role by record id; New Hire pages render that record; progress/start date stored in sessionStorage per preview role.
9. **Invite codes**: shown on Manager Dashboard (`invite-code-card.tsx`) and Settings; entering a code in Settings or sign-up regroups the account.

## Notes
- `src/integrations/supabase/*` are the Supabase helpers: browser client, service-role client, and the auth middleware that validates the bearer token server-side.
- `src/routeTree.gen.ts` is auto-generated by TanStack Router on `dev`/`build`.
